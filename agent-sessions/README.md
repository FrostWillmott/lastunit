# agent-sessions

Exports and logs of the AI agent sessions used to build this project. The spec
asks for prompts or a session export alongside the code and for a visible
timeline, so each session is saved here when it ends, and a final export is
added before submission.

Naming: `YYYY-MM-DD-<short-topic>.<ext>` (jsonl or md). Nothing here is read by
the code or the tooling. Commits a few seconds apart are one working session split
by content (e.g. a docs commit and a feat commit) so the history reads clearly;
the real timeline is the session dates and these exports.

## Что здесь не лежит

Не каждый транскрипт из `~/.claude/projects/` экспортируется. Ни одна из причин
не про содержание работы:

- **Форки и продолжения** одной работы (одна сессия, возобновлённая после
  обрыва) — экспортируется та, что длиннее и содержит результат. Таких четыре.
  У трёх ровно то же время старта, что у экспортированной версии: `7894235d`
  при `22ac11d9` (10.09), `8125a659` при `16b87ad7` (11.09), `ced131f4` при
  `335de095` (11.09). Четвёртый, `15f54139` (10.09), стартует позже — это
  45-секундная попытка возобновиться после обрыва связи («на чём мы
  остановились?»), брошенная сразу же; работа продолжилась в `22ac11d9`,
  который к тому моменту ещё шёл и экспортирован целиком.
- **Файл без сообщений.** `c13a6c2d` (12.09) — две строки метаданных, заголовок
  и имя агента, ноль реплик; сайдкар к `2026-09-12-code-audit` (`a5b505e8`),
  с тем же названием и той же меткой времени. Экспортировать нечего.

Раньше отдельным исключением шли **сессии, где агент вывел `.env` в лог**
(11.09). Теперь это не причина не экспортировать: значения вырезаются, а факт
правки фиксируется — см. «Полный экспорт перед сдачей» ниже.

Всё остальное выгружено целиком. Сверка 14.09 по `sessionId`: 19 транскриптов —
18 в каталоге проекта плюс `a5d8ba06`, сессия скаффолдинга 10.09, шедшая до
переименования репозитория и потому лежавшая в каталоге `-test-FastAPIProject`.
Из них 13 экспортированы, 4 форка и один файл без сообщений исключены по
причинам выше, один — сессия самой сверки, она выгружается при её закрытии.

Повторить счёт по каталогу уже нельзя, и это само по себе вывод: каталог
`-test-FastAPIProject` исчез в ходе сверки — Claude Code подчищает транскрипты,
и между двумя командами одной сессии он удалился вместе с `a5d8ba06`.
Единственная копия той сессии — экспорт в этом каталоге. Поэтому исходники не
резерв: экспорт снимается сразу и целиком.

Сверка нашла две вещи. **Пропуск:** `7bd0359b` (13.09, 06:19–06:49) не был
выгружен, хотя это самостоятельная сессия с двумя коммитами; добавлен как
`2026-09-13-cleanup-and-handover-note`. **Два обрезанных экспорта** — см.
следующий раздел.

Правило, предотвращающее саму причину, — в
`.claude/rules/config-hygiene.md` («Never print a secret's value into a log or
transcript»).

## Полный экспорт перед сдачей (12.09)

Спецификация просит экспорт сессий и видимый ход работы во времени, поэтому
перед сдачей все экспорты приведены к полному виду. До этого пять файлов были
сняты, пока их сессии ещё продолжались, то есть обрывались на середине:

| Экспорт | Было строк | Стало |
|---|---|---|
| `2026-09-10-plan-audit` | 279 | 354 |
| `2026-09-11-backend-stages-0-6` | 3884 | 3908 |
| `2026-09-11-frontend-stage-7` | 1062 | 1143 |
| `2026-09-12-ci-repair-and-hardening` | 1509 | 1555 |
| `2026-09-12-runtime-verification` | 1542 | 1712 |

Ничего не добавлено и не удалено, кроме редактирования секретов ниже; остальные
шесть файлов уже были полными и не менялись.

### Тот же дефект во второй раз (14.09)

Проход 12.09 не вылечил причину, а воспроизвёл её: сессия снимала экспорты, не
закрывшись, поэтому обрезала саму себя. Сверка 14.09 сравнила число строк
каждого экспорта с исходником — проверки, которой в проходе 12.09 не было, —
и нашла два таких файла:

| Экспорт | Было строк | Стало | Чего не хватало |
|---|---|---|---|
| `2026-09-12-runtime-verification` | 1712 | 2037 | 325 строк: та самая работа по экспорту и вырезанию секретов |
| `2026-09-13-badges-language-and-tool-rationale` | 286 | 304 | 18 строк: хвост сессии после снятия экспорта |

Оба пересняты с исходников целиком. К `runtime-verification` заново применена
замена пароля тестовых учёток (35 вхождений вместо 35 в прежнем объёме — в
дописанном хвосте его нет). Хвосты проверены на секреты отдельно: 48-символьных
токенов, какими были мёртвые значения из `.env`, в них нет ни одного.

Вывод в процедуру: **полнота — часть проверки, а не следствие**. Экспорт
сравнивается с исходником по числу строк; валидности JSON и отсутствия секретов
недостаточно, потому что обрезанный файл проходит обе. Экспорт сессии,
снимающей экспорты, неизбежно короче её самой — снимать его должна следующая
сессия.

### Что вырезано

- **Три мёртвых значения** `POSTGRES_PASSWORD` / `PAYSTUB_WEBHOOK_SECRET` из
  локального `.env` от 11.09 — заменены на `<redacted-dead-local-secret>`:
  97 вхождений в `frontend-stage-7` (та самая сессия, где они были напечатаны),
  8 полных и 7 обрезанных отображением в `ci-repair-and-hardening`. Значения
  мёртвые и с текущим `.env` не совпадают — проверено сравнением.
- **Пароль тестовых учёток**, придуманный в сессии проверки, — 35 вхождений в
  `runtime-verification`, заменён на `REDACTED-TEST-PASSWORD`.

### Что намеренно сохранено

Digest образов (64 hex) и SHA закреплённых экшенов (40 hex) остались на месте:
это публичные значения, и без них экспорт перестал бы отражать реальные
команды. Замена делается с проверкой границ токена — 48-символьный секрет
внутри 64-символьного digest'а не трогается. Ловушка не теоретическая: первый
проход резал по подстроке и испортил digest postgres в трёх файлах, потому что
48 его символов совпали с шаблоном; отловлено проверкой и переделано.

### Проверка

Проход 12.09 проверил 11 бывших тогда экспортов на битые строки JSON и на
остатки секретов; полноту он не проверял, что и пропустило два обрезанных файла.

Сверка 14.09 перегнала проверку по всем 13 экспортам, добавив третий столбец:
**0 битых строк JSON, 0 вхождений секретных значений из `.env`, 0 расхождений с
исходником по числу строк** (кроме `2026-09-10-scaffold-and-plan`, чей исходник
уже удалён — сравнивать не с чем). Хук gitleaks проходит. Совпадения демо-учётки
(`shop@example.com` и пароль, дословно равный дефолту из закоммиченного
`.env.example`) и `VITE_API_URL` не в счёт — это опубликованные значения,
напечатанные в самом README проекта.
