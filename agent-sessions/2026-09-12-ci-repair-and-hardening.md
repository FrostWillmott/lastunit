  (`cdace18`) — повторное чтение брони в `start_payment` было no-op: identity map

### CI никогда не проходил

33 прогона `ci.yml` из 33 были провальными, все по 0 секунд. Причина —
`hashFiles()` в `if` на уровне job: это не runtime-ошибка, а ошибка
workflow-файла, GitHub отклоняет файл целиком, прогон завершается без джобов и
без логов, а в `gh run list` выглядит как обычный `failure`. Найдено
`actionlint`. Ещё два дефекта, недостижимых пока workflow не стартует: backend
job вызывал `make check`, который включает `frontend-check` без Node; и `ruff`
не был объявлен в зависимостях — работал только через глобальный бинарник на
PATH, в CI падал с `Failed to spawn`.

- `b3d94d7`, `94d030b`, `1f66887` — фиксы; `ruff` запинен в `==0.16.6` под rev
  pre-commit.
- **Первый зелёный прогон в истории репозитория** — подтверждён
  `gh run watch --exit-status` и проверкой имён всех четырёх джобов.

### Единственный источник для версий

- `.nvmrc` в корне + `engines` + `engine-strict` (`58e96c1`, `44844c4`). Планка
  поднята до 24.15.0 не косметически: `abbrev` и `nopt` в lockfile требуют
  `^24.15.0`, и с `engine-strict` на `>=24` команда `npm ci` падала.
- uv — через `[tool.uv] required-version`, CI читает его `version-file`
  (`affdd7e`). Диапазон `>=0.12.11`; в логе прогона подтверждено, что setup-uv
  разрешает его в наивысшую версию (поставил 0.12.13).
- `.python-version` = 3.12 (`d98ad68`) — интерпретатор не был закреплён нигде,
  и uv брал **системный** python раннера (`Using CPython 3.12.3 interpreter at:
  /usr/bin/python3`).

## Замечание по приватности экспортов

В сессиях от 11.09 (`335de095`, `ced131f4`) предыдущий агент вывел содержимое
`.env` в лог — `POSTGRES_PASSWORD` и `PAYSTUB_WEBHOOK_SECRET`. Значения мёртвые
(не совпадают с текущим `.env`), локальные и в git не попадали; уже
закоммиченный `2026-09-11-frontend-stage-7.jsonl` их не содержит. Эти два
транскрипта не экспортированы намеренно — см. обсуждение в конце этой сессии.

В самом этом транскрипте то же мёртвое значение попало в лог при проверке
(я напечатал его в выводе инструмента). В экспорте вырезано 8 полных и 7
обрезанных отображением вхождений, заменены на `<redacted-dead-local-secret>`.
Редактирование точечное: полные 48-символьные значения и hex после имени
секретного ключа. SHA экшенов (40) и digest образов (64) сохранены — проверено
поимённо, JSONL валиден.

Текущие значения `.env` не печатались нигде: поиск по всем 19 транскриптам и
экспортам дал ноль совпадений. Совпадения `SEED_SHOP_PASSWORD=shop-password` и
`PAYSTUB_WEBHOOK_SECRET=test-secret` в экспортах — это демо-пароль из README и
фикстура из `conftest.py`, опубликованы намеренно.

Чтобы это не повторилось, в `config-hygiene.md` добавлено правило [MUST]: не
печатать значение секрета в лог, потому что экспорты сессий попадают в
репозиторий, а `.gitignore` и gitleaks защищают файл, не транскрипт.
